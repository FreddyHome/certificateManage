# 证书同步：五列执行计划设计

更新日期：2026-11-16。用户已确认并实现；本文件描述最终方案，替代首版“频率表单 + 手动/定时切换”。需求见 [需求第16节](requirements.md#16-证书自动选取与执行计划2026-11-16确认)，模块装配及选证设计见 [主设计第17节](design.md#17-证书自动选取与五列执行计划2026-11-16)。

## 1. 业务交互

执行计划按用户参考图提供五列独立滚动多选：月份、日期、星期、小时、分钟。使用勾选操作，不需要按住Ctrl；每列显示已选数量并提供“不限”按钮。页面不再区分手动和定时，需要立即执行时使用列表中的“执行”按钮。

| 列 | 范围 | 同列规则 |
| --- | --- | --- |
| 月份 | 1–12月 | 多选任意满足；空/全选表示不限 |
| 日期 | 1–31日 | 月内日期；无该日期的月份跳过 |
| 星期 | 周一至周日 | 普通星期，不自动处理法定节假日和调休 |
| 小时 | 00–23 | 所选时区的小时 |
| 分钟 | 00–59 | 所选小时内的分钟，匹配分钟第0秒触发 |

不同列必须同时满足；日期与星期同时指定时取交集。空列、缺省字段和全选统一表示不限。全列不限表示每分钟触发，不表示停用。默认月份/日期/星期不限、小时02、分钟00，时区为北京时间。

| 示例 | 选择 | 含义 |
| --- | --- | --- |
| 每天02:00 | 小时02、分钟00，其余不限 | 每天执行一次 |
| 每周一、周五02:00 | 星期周一/周五、小时02、分钟00 | 在对应星期执行 |
| 1月及3月每天02:00、14:00 | 月份1/3、小时02/14、分钟00 | 每个匹配日期执行两次 |
| 月内15日且是周一02:00 | 日期15、星期周一、小时02、分钟00 | 两个日期条件同时满足才执行 |
| 每月31日02:00 | 日期31、小时02、分钟00 | 只有存在31日的月份执行 |

## 2. 保存、状态与历史任务

- 草稿只保存计划参数，不运行；任务设为“就绪”并保存后按所选计划自动执行。
- 五列计划在服务端根据任务状态派生是否启用；用户不需要另选执行方式。手动执行仍需任务就绪，并遵守同任务互斥与配置校验。
- 既有未启用任务不因升级、查询、打开编辑或预览被批量启用；用户以就绪状态在新界面保存后启用。未启用的历史计划在列表明确标注。
- 旧常用频率可无损回显为五列，包括每天、每周、月内日期、每小时和固定分钟间隔；无法无损转换的月末、秒级或复杂表达式保留为CUSTOM。
- CUSTOM显示原规则提示及折叠的高级设置；支持明确选择“改用月份、日期和时间选择”。打开或取消编辑不修改原规则。秒级旧规则的预览和下次时间显示到秒。
- 不新增法定节假日、一次性预约或失败自动重试功能。

## 3. 中文规则与时间预览

五列、时区变化后防抖300毫秒请求服务端预览。界面显示当前中文规则，以及包含年月日、星期、时分的最近三次计划时间；所有时间按计划时区显示，CUSTOM保留秒数。

草稿同样允许预览，并注明“草稿预览，尚未启用”。预览不要求填写任务名称、证书、服务器或步骤，不保存任务、不创建执行实例、不执行远端操作。认证和审计仍沿用现有系统机制。

参数变化立即清除旧成功结果；等待期间显示更新中，失败显示服务端业务原因。递增请求序号保证过期响应不覆盖新结果，卸载后不再回写。保存校验区域不重复显示旧规则的时间，实时预览作为唯一编辑时间来源。

服务端按计划时区使用同一调度解析器处理跨月、闰年及夏令时；不以浏览器时区推算。不合法数值/时区、超范围选择，以及整个组合没有未来触发时间时拒绝预览和保存。

## 4. API与存储

`POST /api/v1/sync-tasks/schedule-preview` 接收计划对象，受会话、ADMIN与CSRF保护：

```json
{
  "frequency": "CALENDAR",
  "months": [],
  "monthDays": [],
  "weekdays": [1, 5],
  "hours": [2],
  "minutes": [0],
  "timezone": "Asia/Shanghai"
}
```

星期1–7分别表示周一至周日。返回规范化schedule、cron、timezone、中文summary和nextTimes（三次时间，含时区及偏移）。新计划秒固定0；例子派生`0 0 2 * * 1,5`。

`SchedulePlan.normalize`统一校验、去重排序及生成摘要和表达式；空或全范围归一为不限。日期、月份、星期保留精确枚举，仅小时、分钟的完整等距选择可使用步长压缩，不改变匹配集合。

`WorkflowService.save`在同一事务保存schedule_json与派生cron/timezone/next_fire_at，保留修订号冲突检查。CALENDAR以任务状态派生schedule_enabled；前端摘要及冗余cron不作为权威输入。旧频率和旧API请求保留兼容逻辑。

- V11：新增`sync_tasks.schedule_json CLOB`，允许空值以兼容旧记录。
- V12：将`cron`扩为`VARCHAR(500)`，容纳多列多选和兼容自定义规则。
- 两次迁移不新增表，不重写旧表达式、不批量启用旧任务。查询通过旧规则解析或结构化参数返回schedule与scheduleSummary。

## 5. 列表和运行语义

列表显示中文“执行计划”和“下次计划时间”，保留编辑、执行、记录、删除。时间按计划时区格式化，旧秒级计划显示秒；未启用历史计划注明“未启用”，没有下次时间时显示空占位。

计划时间表示触发入队时间，不保证该时刻立即开始或成功。同一任务最多一个排队/运行实例；前次未结束或证书/服务器不可用时记录未入队原因。失败不自动重试，远端已经发生的写入不回滚。

到期扫描先推进未来时间，再单次尝试入队。停机遗漏不逐次补跑；恢复时可能处理一次已到期触发。重启将中断实例标记为中断，不自动重放远端操作。每次入队仍重新按配置选证，并冻结当次证书与连接快照。
