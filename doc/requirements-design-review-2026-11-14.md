# 需求与设计核对基线

核对开始：2026-11-14；复核完成：2026-11-15。范围：整个证书管理项目，包括后续服务器同步、业务组件、审计与 SSH 扩展。

## 1. 核对结论与依据

核心业务已有实现和对应自动化测试，主要问题是早期主文档与后续增量设计没有汇总，另有少量需求缺口和未落地的设计建议。不能将“代码存在”“自动化通过”“真实业务验收通过”视为同一状态。

本次以最新明确用户要求、已确认补充需求为优先依据，对照当前源码、迁移及既有验收记录核对。实现中的默认值仅记为实际行为，不因此认定用户已经确认。历史文档保留原阶段背景，冲突项按下表说明处理。

本轮仅修改文档，未修改代码、运行配置或业务数据，未重新执行测试或重启服务。

### 2.1 Shell 执行的明确边界

- 用户已明确：独立步骤、无文件输入、步骤固定参数；服务器在菜单配置，组件只选择服务器。
- 实现默认值：执行超时 60 秒，允许 1–300 秒；服务器连接及认证超时分别配置；每路输出保留前 1 MiB，继续排空并标明截断。
- 以远端最终退出码 0 判定成功；非 0、信号退出、缺少退出码、超时或连接失败均失败并停止后续步骤。
- 多行命令原样交远端解释，不自动插入 `set -e`；不提供交互终端、提权输入或前序步骤变量替换。
- 超时关闭连接并保留已收输出，不能保证远端后台/衍生进程被终止；不自动重试。
- 命令与输出进入加密详情，普通执行结果保存摘要。

### 2.2 已有实现默认值，不等同于新增需求确认

| 项目 | 已核实的实现行为 |
| --- | --- |
| 资产模型 | 单用途、客户资产单客户；公钥材料共享，资产隔离；CN 必须唯一存在，否则拒绝 |
| 链与时间 | 导入支持多层中间 CA；结构验证与当前时间状态分开，允许登记已过期材料，但链有效区间须有交集；业务使用另查有效性 |
| 签发 | 创建固定 RSA 3072 / SHA-256；父 CA 必须具备私钥和签发资格，子有效期不超父级 |
| 导出 | 公钥 PEM/链 PEM/DER/P7B，自有含私钥 P12 使用至少 8 位导出密码；无裸私钥导出入口 |
| 密码约束 | 旧通用 Store 至少 8 位；新 IS 业务组件允许匹配目标系统的非空密码；JKS 可独立 Key 密码，PKCS12 要求一致 |
| 通知 | 默认关闭；默认节点 30/14/7/1 天，Asia/Shanghai 09:00；CA 范围可配置；不补历史节点、不提醒已过期证书；失败按 15 分钟间隔、自动投递最多 3 次 |

## 4. 实现差异和待决事项

### R01：证书管理信息后续维护存在需求缺口

主需求第 3.3 节写明可维护用途、关联业务和备注。当前 `CertificateController` 有列表、详情、导入、签发、导出、启停、归档和删除接口，未找到修改这三类管理字段的独立入口；`CertificateView.vue` 同样没有相应编辑操作。用途可在创建/导入时选择，不等于后续可编辑。

该项属于“原需求与当前入口存在差异”，本轮没有擅自取消需求或增加功能。需决定继续作为必需项补齐，或正式记录不纳入当前版本。若实施，必须明确是否允许变更用途及其对 TN 自动选证、既有同步配置和提醒的影响。

### R02：分页、错误返回、健康检查及密钥轮换没有完整按早期设计落地

- 主设计第 8 节描述统一 `items/total/page/pageSize`，当前证书列表接口直接返回数组，筛选主要在前端进行；客户表有前端分页，自有三表没有独立分页。
- 设计描述统一 `code/message/fieldErrors/requestId`，当前 `Errors` 主要返回 `message`；远端连接测试单独提供诊断代码及阶段。
- 设计提及健康检查和按 key_id 轮换，当前依赖未接入 Actuator，`SecretStore` 只加载一份主密钥，未发现轮换入口。首页/API 冒烟检查不等于已有独立健康检查接口。
- 登录限流在早期设计提到，但 README 已列为当前范围之外；本轮未将其擅自纳入改造。

上述多数属于早期设计方案与实现取舍不一致，不能仅凭设计出现过就宣称用户已经确认必须实施。需要在下一轮确定是否升级为交付要求。数据规模决定是否必须改为后端分页。

### R03：新建任务是否仍需添加通用 SFTP 步骤

当前界面能添加三个业务组件及 Shell；旧通用 SFTP 任务继续可编辑执行，后端仍支持 UPLOAD/MOVE/READ。该行为符合此前“三业务组件替代新建通用组件、保留旧任务”的设计。若今后要求从空白任务直接新增独立 SFTP 上传/移动/读取，需明确恢复对应入口；不能将“后端兼容”当成“新建界面已开放”。

### R04：运维与外部契约仍有待验收项

- 真实 SMTP TLS/账号/收件箱到达、真实 IS 写入及重载、真实 TN 更新和链顺序仍需目标环境验证；本地 HTTP/SFTP/SSH 测试不能代替。
- `doc/rest-api.md` 是外部 IS/TN 接口记录，不是本项目全部 REST API；其中远端必填约束、鉴权策略及失败报文仍有待确认项。本项目校验器的必填规则不能代替远端契约确认。
- 最新 SSH 用户要求已清楚，但尚无真实目标 SSH 服务器的联调验收记录。
- 既有验收记录说明浏览器点击验收未完成或受工具限制；静态分包可加载不等于所有页面交互已验收。
- 数据规模、备份周期及恢复演练、审计保留期限和原始日志存储容量仍需部署约定；当前日志不自动清理。

## 5. 迁移及验证证据

当前迁移为 V1–V10：V1 基础数据；V2 逻辑删除；V3 服务器及秘密版本；V4 流程和执行快照；V5 统一日志；V6 客户外部标识；V7 启用状态；V8 归档；V9 加密原始审计；V10 SSH 类型约束。

SQL 与表数量通过静态解析实际迁移核对；V10 位于 `src/main/java/db/migration/V10__ssh_shell_steps.java`，不新增表。

已存在的最近完整验证记录为 2026-11-13 的 `logs/ssh-final-verify.log`：后端 102 项、前端 24 项通过，生产构建及 Java 格式检查通过。此为历史证据，本次没有重跑。运行包验收与重启记录分别见该次日志及本聊天最近一次重启结果，不能用历史 PID 代表当前服务进程。

建议后续交付按“需求条目 → 设计规则 → 实现位置 → 自动化测试 → 目标环境验收”追踪；历史测试数量随版本增长，不覆盖为同一数字。

## 6. 后续优先级

1. 先确定 R01 是否仍为必需需求，以及 R03 是否需要恢复新建入口；这两项会改变用户可完成的业务动作。
2. 补目标 SMTP、IS、TN、SSH 联调及浏览器交互验收，记录目标环境、输入、期望与实际结果。
3. 根据数据规模决定后端分页、错误结构、健康接口及运维能力；明确日志容量与备份恢复制度。
4. 本文作为当前核对入口，旧设计作为演进记录保留，后续新需求继续标注用户要求、默认选择和验收证据。
