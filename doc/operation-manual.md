## 1. 使用准备与首次登录

### 1.1 准备材料

根据要完成的业务，提前准备以下材料：

| 业务 | 所需材料 |
| --- | --- |
| 导入自有证书 | 从根到叶子的完整证书链、终端私钥及按需提供的解密密码，或包含这些材料的 P12/PFX |
| 管理客户证书 | 客户名称、证书用途、完整公钥证书链；不要上传客户私钥 |
| 更新 IS keyStore | 含私钥的自有叶子证书、目标 HTTP 服务器、IS 中的库名称、文件全路径、库密码及私钥密码 |
| 更新 IS truststore | 客户证书链、原库位置及密码、读取服务器、目标 HTTP 服务器、IS 中的库名称 |
| 更新 TN 证书 | 客户证书链、客户在 TN 中使用的外部 ID 和 idType、目标 HTTP 服务器 |
| 发送提醒邮件 | SMTP 地址、端口、加密方式、发件账号和收件地址 |

“叶子证书”也称终端证书，代表实际用于业务通信的证书；根证书和中间证书用于构成其签发链。

### 1.2 启动和登录

1. 已部署的系统使用管理员提供的访问地址。默认本机地址为 `http://127.0.0.1:8080`。
2. 尚未启动时，按[服务维护](#12-服务维护备份与升级)执行启动脚本。
3. 首次初始化账号为 `admin`，初始密码为 `123456`。已有系统使用当前密码，重启不会恢复初始密码。
4. 登录后，建议立即通过右上角“修改密码”修改初始密码。依次输入原密码和至少 6 位的新密码，再重新登录。

当前所有登录用户均为管理员，客户不登录本系统。

### 1.3 常用入口与操作顺序

| 菜单 | 主要用途 |
| --- | --- |
| 客户证书 | 导入、查询、导出客户公钥证书链 |
| 自有证书 | 导入或创建根、中间、叶子证书，管理自有私钥 |
| 客户管理 | 维护客户名称及对接标识 |
| 证书同步 | 配置流程、执行计划，立即执行并查看结果 |
| 服务器管理 | 维护 HTTP、SFTP、SSH 连接配置并测试 |
| 归档证书 | 查看、导出、恢复或删除已归档资产 |
| 系统管理 | 审计日志、用户管理、SMTP配置、通知服务 |

首次配置同步业务时，按“客户信息 → 证书材料 → 服务器 → 同步任务 → 执行结果 → 目标系统核验”的顺序操作。邮件提醒可单独配置。

## 2. 客户管理

1. 打开“客户管理”，点击“新增客户”。
2. 填写客户名称，按需填写“ID（可选）”“idType（可选）”和描述，然后保存。
3. 通过客户名称搜索已有客户，点击“编辑”修改信息。

普通证书归属管理可只填客户名称。需要更新 TN 证书时，必须填写与 TN 合作伙伴外部标识一致的 ID 和 idType；这里的 ID 不是本系统生成的客户记录编号。

导入客户证书时，也可以在“所属客户”中选择已有客户或直接输入新客户名称。新客户随证书保存一并创建；后续可在客户管理补充对接标识。

## 3. 自有证书

### 3.1 查看资产

打开“自有证书”。页面按根证书、中间证书、叶子证书分别展示，证书名称取自证书实际 Subject 中的 CN。相同 CN 的新旧证书可以同时存在，应结合序列号、SHA-256 指纹和到期时间区分。

证书列表按到期时间升序展示。列表中的较早到期记录，不代表自动同步时一定选择该记录；自动选证规则见[IS keyStore 更新](#72-is-keystore-更新)。

根、中间、叶子三张表各自每页20条，通过各表下方分页条翻页。客户证书与归档列表同样每页20条。搜索和筛选由服务器执行，调整条件后回到第一页；输入搜索内容后稍等约300ms即可加载结果。操作导致当前页没有记录时会自动回到有效页面。

### 3.2 导入已有证书

1. 点击“导入”，选择对应材料格式。
2. 按下表上传材料。分文件模式可通过“＋ 新增一行”增加证书文件。
3. 选择证书用途：AS2、HTTPS 或通用。
4. 点击“校验预览”，核对解析出的完整链、各节点 CN 和有效期；上传私钥时确认匹配结果。
5. 确认材料和用途正确后点击“保存”，再从列表打开详情核对。

| 导入模式 | 操作要点 |
| --- | --- |
| CER / DER / CRT / PEM | 上传构成链的证书文件，并在“终端证书私钥”中上传对应私钥，按需填写私钥密码 |
| P7B / P7C | 上传证书容器，并另行上传终端私钥；容器本身不含私钥 |
| P12 / PFX | 上传包含证书链及私钥的容器，按需填写证书库密码 |

当前自有证书导入界面要求提供终端私钥。系统根据证书内容识别签发关系，不按上传文件顺序拼接链。链不完整、签名不正确、密码错误或私钥不匹配时，先修正材料再保存。链中的上级 CA 如仅保存公钥，不能作为签发私钥使用。

默认单文件上限为 5MB、单次请求上限为 25MB。导入完整链只表示材料之间的签发关系通过校验，不代表外部业务系统已经信任该链；系统不进行在线吊销状态查询。

### 3.3 创建证书

按根 → 中间 → 叶子的顺序创建：

1. 在根证书区域创建根证书，填写 CN、用途、有效天数及可选主体信息，提交“创建证书”。根证书为自签名证书。
2. 在中间证书区域创建中间证书，选择可用根证书作为上级，再填写本证书的信息并提交。
3. 在叶子证书区域创建叶子证书，选择可用中间证书作为上级，再填写业务证书信息并提交。
4. 用于 HTTPS 的叶子证书还需填写 SAN，多个域名或 IP 用逗号分隔。

主体信息中，CN 为必填；国家/地区 C 使用两位代码，例如 `CN`；省/州 ST、城市 L、组织 O、部门 OU 按需填写。新证书的有效期不能超过上级证书。

当前签发使用 RSA 3072 和 SHA256withRSA。上级必须启用、处于有效期内并具有签发私钥。若提示“暂无可用上级”，先创建或导入符合条件的上一层证书。

### 3.4 查看与导出

点击“查看”进入证书详情，通过链节点切换查看根、中间或叶子的 Subject、Issuer、序列号、指纹、SAN 和有效期，并确认是否保存私钥。

在“导出”中按接收方要求选择：

| 选项 | 内容 |
| --- | --- |
| 证书链 PEM | 公钥证书链 |
| 证书 DER | 当前证书的二进制公钥材料 |
| 证书库 P7B | 公钥证书链容器 |
| 含私钥 P12 | 具有私钥的资产可选，包含私钥及证书链；需输入至少 8 位导出密码 |

导出密码是本次生成文件的保护密码，交付文件时需按接收方的安全方式传递。

## 4. 客户证书

### 4.1 导入和核对

1. 打开“客户证书”，点击“导入”。
2. 选择 CER / DER / CRT / PEM 或 P7B / P7C，上传完整公钥链。
3. 选择或输入所属客户，选择 AS2、HTTPS 或通用用途。
4. 点击“校验预览”，核对客户、叶子 CN、序列号、有效期及上级链。
5. 点击“保存”。列表主要展示终端证书，展开或进入详情可查看上级链。

客户证书不支持 P12 / PFX 和私钥导入。导出公钥材料的操作与自有证书对应选项相同。

### 4.2 客户换证

1. 将新证书完整链作为新资产导入，关联到同一客户、同一用途。
2. 确认新链已启用，且叶子及所有上级证书均已生效、未过期。
3. 检查关联任务是否选择“自动选择到期最晚的可用链”。自动模式会在下一次入队时重新选证；指定链模式需人工修改引用。
4. 执行并核对目标系统结果后，再根据业务需要停用或归档旧证书。

新旧证书独立保存，不会因导入新证书而自动删除或替换旧记录。自动选证按同一客户和同一用途筛选，不要求新旧客户证书 CN 相同。

## 5. 停用、归档、恢复与删除

| 操作 | 入口与效果 |
| --- | --- |
| 停用 | 在证书列表关闭启用开关；仍可查看、导出，不再作为可用签发、同步或通知资产 |
| 归档 | 在证书列表点击“归档”并确认；移入“归档证书”，停止签发、同步和通知 |
| 恢复 | 在“归档证书”点击“恢复”；回到普通列表，保留归档前的启用状态 |
| 删除 | 仅在“归档证书”中操作并确认；执行引用检查，通过后逻辑删除，保留历史材料与审计 |

删除被其他证书链、任务或正在执行业务引用的资产时，系统可能拒绝操作。根据提示先处理引用，不直接修改数据库。归档、停用不用于撤销已经下发到目标系统的证书，也不会撤回已入队任务冻结的材料。

## 6. 服务器管理

### 6.1 新增连接

1. 打开“服务器管理”，点击“新增服务器”。
2. 填写唯一别名、协议、说明，开启“启用”。协议保存后不能直接更换。
3. 按协议填写连接与认证参数，点击“保存”。
4. 在列表点击“测试”，根据结果修正地址、网络、认证或超时配置。

| 协议 | 主要字段 | 测试范围 |
| --- | --- | --- |
| HTTPS / HTTP | 基础地址、测试路径/方法、NONE/BASIC/BEARER 认证、连接及读取超时 | 使用保存的配置发起 GET 或 HEAD 请求，检查连接、认证及预期状态码 |
| SFTP | 主机、端口、用户名、PASSWORD/KEY 认证、连接及读写超时 | 建立连接、认证并打开 SFTP 会话，不上传文件 |
| SSH / Shell | 主机、端口、用户名、PASSWORD/KEY 认证、连接及认证超时 | 建立 SSH 连接并认证，不执行任务命令 |

KEY 认证填写 SSH 私钥及按需填写私钥口令。SSH 登录密钥与业务 X.509 证书私钥用途不同。

已保存密码、令牌、私钥等凭据在编辑时留空会保留。确需移除时，勾选对应“清除”选项再保存。“填入协议默认字段”会重置编辑中的协议参数，使用后需重新核对。

### 6.2 HTTP 配置要点

- 基础地址填目标服务地址，例如 `https://is.example.com:5555`；任务中的 URL 使用该地址下的接口路径。
- Basic 认证填写用户名和密码；Bearer 认证填写令牌。
- 需要自定义请求头或测试状态码时，编辑相应 JSON，点击“应用 JSON”后再保存。
- HTTPS 会校验证书和主机名；内部 CA 场景可在“信任的客户证书”中配置额外信任材料，访问地址仍需与服务端证书匹配。

当前内部自管理场景的 SFTP/SSH 不校验主机公钥指纹。连接测试成功只证明测试范围内可用，不能证明远程文件有读写权限、业务接口有更新权限或命令执行一定成功。

被任务引用的服务器不能直接删除。可编辑连接信息或停用；停用后，相关任务不能正常使用该连接。

## 7. 创建证书同步任务

### 7.1 共用操作

1. 打开“证书同步”，新建任务，填写名称和说明，配置期间保持“草稿”。
2. 设置执行计划，具体规则见[第 8 节](#8-设置执行计划)。
3. 按业务点击“添加 IS truststore 更新”“添加 IS keyStore 更新”“添加 TN 证书更新”或“添加 Shell 命令执行”。
4. 填写步骤名称和组件参数。多个步骤按界面从上到下执行，可上移、下移、复制或移除。
5. 点击“保存并校验”，查看校验结果并修正问题。该操作会保存任务，建议在草稿状态完成配置核对。
6. 准备投入运行时，将状态改为“就绪”并保存。保存后自动启用执行计划，也可通过列表“执行”立即发起一次。

任务没有“手动/定时”方式切换。“草稿”不能执行；“就绪”保存后会自动按计划运行，不能理解为只允许手动执行。校验通过不代表已调用目标接口或完成目标系统更新。

### 7.2 IS keyStore 更新

适用于向 IS 下发自有业务私钥及完整证书链。

1. 添加“IS keyStore 更新”，选择 PKCS12 或 JKS 格式。
2. 填写与目标 IS 配置一致的库密码和私钥密码。PKCS12 两者必须一致；编辑已有密码时留空保留。
3. 选择证书方式：
   - **自动选择同 CN 到期最晚的可用链**：选择“匹配 CN 的基准叶子证书”。
   - **指定证书**：选择固定自有终端证书，不进行自动换新。
4. 核对预览的链及到期时间。别名可留空，留空使用叶子 CN；目标系统依赖固定别名时填写对应值。
5. 选择“HTTP 目标服务器”，填写更新 URL、`keyStoreName` 及“写入文件全路径 path（包含文件名）”。
6. 保存、校验并执行后，在目标 IS 中核对库条目、证书序列号、有效期及加载状态。

自动模式每次入队都按基准叶子的实际 CN 精确匹配自有叶子证书，不附加用途条件。候选必须含私钥、已启用、未归档/删除，且整链当前均有效；按叶子到期时间最晚者选择，到期相同时选择资产 ID 较大者。基准后续过期、停用、归档或软删除，仍可用于确定匹配 CN；没有符合条件的候选时本次入队失败。

例如旧证书 CN 为 `as2.example.com`，新导入证书的实际叶子 CN 相同、整链有效且到期更晚，下一次入队即可采用新证书，无需等待旧证书过期。新证书尚未生效时不会被选中。系统不会自行签发、续期或下载新证书。

本组件创建的 keyStore **仅包含所选私钥及其完整链**，不会合并目标原库的其他私钥条目。配置前需确认目标库的预期内容。旧通用“制作 Keystore”任务中的固定条目不会自动变为按 CN 选证。

### 7.3 IS truststore 更新

适用于读取原信任库，在保留其他内容的基础上导入客户公钥证书。

1. 添加“IS truststore 更新”。
2. 在读取阶段选择 SFTP 或 HTTP 来源、来源服务器和原库文件全路径。HTTP 来源还需填写读取 URL，系统自动将文件路径作为 `path` 查询参数传入。
3. 填写原 truststore 密码。按需勾选“删除原 truststore 中已过期的证书”；不勾选时不执行该清理。
4. 选择客户、证书用途及“自动选择到期最晚的可用链”或“指定证书链”。
5. 核对链节点，默认全选。手动改变节点勾选会固定当前链；需要后续自动换新时，应保持自动选链和默认完整链配置。
6. 选择写入阶段的 HTTP 目标服务器，填写更新 URL 和 `keyStoreName`。写入使用读取阶段返回的同一文件路径。
7. 保存、校验并执行，在目标 IS 中核对原有条目、导入条目和重载结果。

自动模式按同一客户、同一用途筛选已启用、未归档/删除且整链当前有效的资产，选择叶子到期最晚的链，到期相同时选择资产 ID 较大者。每次入队重新查询。

导入条目别名自动使用 CN 与 SHA-256 指纹，重复证书不会重复插入。原库其他条目通常保留，别名冲突等异常以执行结果为准。HTTP 读取接口应返回整个库文件的 Base64 内容。

### 7.4 TN 证书更新

1. 在“客户管理”核对客户的外部 ID 和 idType，确保可定位目标 TN 合作伙伴。
2. 添加“TN 证书更新”，选择客户和证书用途。
3. 选择自动到期最晚链或指定链，核对完整链及页面展示的客户标识。
4. 选择 HTTP 目标服务器和更新 URL，保存、校验并执行。
5. 在 TN 中核对实际合作伙伴的证书记录及业务使用结果。

本组件提交从根到叶子的完整公钥链，不传私钥；自动选证条件与 IS truststore 相同。当前对接程序只更新目标已有的 sign、decrypt、ssl 证书记录，缺失记录可能被跳过。因此接口返回成功后，还需核对 TN 中应更新的记录是否实际存在并已换证。

### 7.5 对接接口路径

以下为目标 IS 对接程序提供的接口，不是证书管理系统自身的 `/api/v1` 接口：

| 操作 | 方法及路径 |
| --- | --- |
| 读取原证书库 | `GET /restv2/wm.certificate:cert/keystore/get` |
| 写入并重载证书库 | `POST /restv2/wm.certificate:cert/keystore/update` |
| 更新 TN 证书 | `POST /restv2/wm.certificate:cert/tn/update` |

业务组件更新成功需同时满足 HTTP 2xx 和响应 `code=0`。IS 更新自动传入 `type=key` 或 `type=trust`，密码需与 IS 原配置一致，不作为更新接口独立密码字段传入。

目标写入接口要求原文件已存在，会先重命名备份，再写入并重载；失败不会自动回滚。部署权限、请求响应字段及示例见[对接端三个 API 说明](../integrations/README.md)。

### 7.6 Shell 命令执行

1. 在服务器管理中配置并测试 SSH / Shell 服务器。
2. 添加“Shell 命令执行”，选择启用的 SSH 服务器。
3. 输入远程命令，可填写多行；设置执行超时，默认 60 秒，可选 1–300 秒。
4. 确认步骤顺序。需要先下发证书再执行维护命令时，将 Shell 放在更新步骤后。
5. 执行后查看退出码、标准输出及标准错误。

远程退出码为 0 才判定成功；非 0、连接失败或超时判为失败，并停止后续步骤。命令没有交互式终端，应能独立执行。超时不保证远端后台子进程已结束，重跑前需核对远端实际状态。输出以 UTF-8 记录，单个输出流最多保留 1MiB。

已有通用证书库、SFTP 和 HTTP 步骤继续兼容；新建任务优先使用上述业务组件。SFTP 文件写入成功本身不能证明目标应用已加载证书。

## 8. 设置执行计划

### 8.1 五列选择规则

执行计划使用“月份、日期、星期、小时、分钟”五列滚动多选，普通操作无需填写 Cron 表达式。

| 列 | 可选范围 | 示例 |
| --- | --- | --- |
| 月份 | 1–12 月 | 只选 1、7，表示只在这两个月运行 |
| 日期 | 每月 1–31 日 | 只选 1、15，表示每月这两天 |
| 星期 | 周一至周日 | 选周一至周五，表示按星期限定 |
| 小时 | 00–23 | 选 02、14，表示这两个小时 |
| 分钟 | 00–59 | 选 00、30，表示这两个分钟 |

- 同一列选多个值，满足任意一个即可；不同列必须同时满足。
- 一列不选具体值或全选，均表示该列“不限”。五列全部不限表示**每分钟执行**，不是关闭计划。
- 日期和星期同时选择时取交集。选择“每月 1 日”及“周一”，只在恰好为周一的每月 1 日执行。
- 当月没有所选日期时跳过，不自动挪到月末；例如选 31 日，4 月不会执行。完全没有未来执行时间的组合不能保存。
- 按星期不处理法定节假日或调休。新计划在对应分钟的第 0 秒触发。

### 8.2 常用设置示例

以下示例使用北京时间 `Asia/Shanghai`：

| 业务时间 | 月份 | 日期 | 星期 | 小时 | 分钟 |
| --- | --- | --- | --- | --- | --- |
| 每天凌晨 2 点（新任务默认值） | 不限 | 不限 | 不限 | 02 | 00 |
| 每周一、三、五上午 9 点半 | 不限 | 不限 | 周一、周三、周五 | 09 | 30 |
| 每月 1 日和 15 日凌晨 2 点 | 不限 | 1、15 | 不限 | 02 | 00 |
| 每天 8 点和 18 点各运行一次 | 不限 | 不限 | 不限 | 08、18 | 00 |
| 每小时整点和半点 | 不限 | 不限 | 不限 | 不限 | 00、30 |
| 每年 1 月和 7 月的 1 日凌晨 2 点 | 1、7 | 1 | 不限 | 02 | 00 |

### 8.3 预览与启用

1. 选择时区，再调整五列。
2. 查看中文规则和最近三次具体时间，核对日期、星期和时分。
3. 草稿也可预览，预览不保存任务、不执行同步，也不要求业务字段全部填完。
4. 点击保存才写入设置；以“就绪”状态保存后，计划自动启用。

若需要暂停后续自动触发，将任务改为“草稿”并保存；这不会撤回已排队或正在执行的实例。需要立即执行时使用列表“执行”，无需修改计划时间。

旧任务中可以无损转换的计划会显示五列。月底、秒级等特殊规则仍保留在折叠的高级设置中，继续按原规则运行；只有明确需要改写时才转换。旧未启用计划不会因打开页面、预览或升级而启用，以就绪状态重新保存后才按新界面规则启用。

## 9. 执行任务与查看结果

### 9.1 立即执行

1. 在“证书同步”列表确认任务为“就绪”，检查中文计划及下次计划时间。
2. 点击该任务的“执行”。提交成功代表已入队，不代表目标系统已经更新。
3. 点击“记录”，选择“查看 / 刷新”，查看本次执行和各步骤状态。
4. 需要进一步排查时点击“查看执行审计日志”。
5. 执行成功后，到目标 IS/TN 核对证书、库内容及业务加载结果。

| 状态 | 含义及处理 |
| --- | --- |
| 草稿 | 只保存配置，不能执行 |
| 就绪 | 可以入队；已启用的计划可自动触发 |
| 排队中 | 等待执行，稍后刷新 |
| 执行中 | 步骤正在运行，避免重复发起 |
| 成功 | 流程步骤成功，继续核对目标业务效果 |
| 失败 | 查看失败步骤和审计详情，处理原因后再决定重跑 |
| 已中断 | 例如服务重启导致运行中断，先核对目标实际状态 |
| 已跳过 | 前置步骤失败等原因导致该步骤未执行 |

### 9.2 自动选证与执行边界

计划触发和列表“执行”遵循相同的选证规则。**在入队时**查询并冻结所选资产、完整链和私钥引用；入队后导入新证书，只影响后续执行，不更改本次材料。

同一任务最多有一个排队或执行中的实例，不能并行执行；前次未结束时，本次可能无法入队。计划时间是触发入队时间，不保证立即开始或成功。

后台默认允许2个独立任务同时执行；两个任务使用相同目标服务器时会串行，等待期间显示“排队中”。容量可由维护人员通过`SYNC_PARALLELISM`调整，重启后生效。不要为缩短排队而重复点击执行。

一个步骤失败后，后续步骤停止，任务不会自动重试，也不会自动撤销已完成的远程写入。服务重启不会重放已产生的远程效果；停机期间错过的计划不会逐次补跑，恢复扫描时可能处理一次已到期触发，再推进后续计划。

### 9.3 失败后处理

1. 保存执行 ID、失败步骤、时间和错误摘要。
2. 查看审计详情，判断失败发生在选证、连接、认证、读取、写入、重载还是命令阶段。
3. 对于写入、重载、TN 更新或 Shell 已开始的情况，先检查目标实际状态和备份文件。
4. 修正证书、服务器、路径、密码或目标配置，重新校验。
5. 确认再次执行不会造成不期望的重复操作后，通过列表“执行”重新发起，并核对最终结果。

## 10. 到期邮件提醒

### 10.1 配置并测试 SMTP

1. 打开“系统管理 → SMTP配置”。
2. 填写 SMTP服务器、端口、STARTTLS/TLS、发件邮箱、账号和认证密码。
3. 点击“保存配置”。已有认证密码留空不修改。
4. 在“发送测试邮件”区域输入测试收件邮箱，点击“发送测试邮件”，并核对实际收信。

测试使用已保存配置，编辑后未保存的参数不会用于测试。

### 10.2 设置通知规则

1. 打开“系统管理 → 通知服务”，开启“启用提醒”。
2. 填写收件人，多个地址用逗号分隔。
3. 设置“提前提醒天数”，默认 `30,14,7,1`，表示分别在到期前这些天提醒。
4. 核对每日检查时间和时区，默认北京时间每日 `09:00:00`。
5. 设置“即将过期状态阈值（天）”；该值用于状态判定，与具体发信节点分开设置。
6. 按需开启“包含自有CA证书提醒”，点击“保存规则”。
7. 需要立即检查当天节点时，点击“检查今日节点”，再查看发送记录。

系统默认关闭提醒。开启后在当天检查时间到达后扫描，后台按分钟检查。“检查今日节点”只处理今日已经到检查时间的提醒节点，不是强制给所有证书发信，也不补发历史提醒。

### 10.3 查看记录与重试

发送记录显示证书名称、收件人、提前天数、状态、尝试次数及失败原因。点击“刷新”更新；状态为 `FAILED` 时可点击“重试”。

新旧证书分别提醒；同一资产、节点、收件人及到期时间组合发送成功后去重。已过期后不反复发送到期提醒。发送失败间隔约 15 分钟自动重试，当前实现累计尝试 3 次后转为失败（包含首次发送）；处理故障后可手动重试。停用、归档或删除的资产不再参与正常提醒。

## 11. 用户管理与审计日志

### 11.1 用户维护

在“系统管理 → 用户管理”点击“新增用户”，填写用户名及至少 6 位初始密码并保存。列表可“停用/启用”账号或“重置密码”；用户本人通过右上角“修改密码”修改自己的密码。

当前没有角色权限配置，新增账号同样具有管理员权限。账号停用后不可继续访问系统。

### 11.2 查看审计

在“系统管理 → 审计日志”按页面提供的条件查询操作、同步及通知记录，核对执行人、时间、内容、来源和结果，进入详情查看诊断信息。手动执行归属发起用户，计划执行归属系统。

需要分析 HTTP 请求响应或 Shell 输出时，查看对应执行审计详情。系统按当前功能保存相关原始内容并加密存储，详情仍可能包含业务材料，不宜直接公开分享。历史日志未保存的原文和诊断无法追补。

审计页面只读，不提供修改或删除。数据库中的审计记录与服务器文件日志分开存储。

使用“上一页/下一页”连续浏览；更改筛选或点击刷新后回到首页。详情中的“刷新详情”可重新读取后台补写结果。出现待写提示时，表示系统存在尚未入库的原始审计，不是当前记录的精确完成进度；稍后刷新确认。旧版本从未采集的原文仍无法补回。

### 11.3 查看性能与处理审计积压

管理员登录后可在同一会话读取`GET /api/v1/system/performance`，查看API次数/错误及耗时、连接池等待与超时、任务/通知积压、审计待写数量与字节、HTTP复用和JVM/GC。API的p50/p95为累计直方图桶上界估计，重启后清零；队列采样最多缓存5秒，池饱和时可能返回之前的快照。该接口不触发同步或邮件，不包含业务正文及凭据。

数据库暂不可用时，已接收审计保存在默认`data/audit-outbox`的加密文件中，数据库恢复或服务重启后自动补写，不会因此重新执行远程操作。每类待写上限1GiB/10000文件；若报告积压已满，先检查磁盘、目录权限及数据库故障，恢复写库，切勿通过删除待写文件腾空间。

停机备份时必须保留整个data和原主密钥；自定义主密钥位置时，还需备份其同级`audit-outbox`目录。已验证进程退出后的恢复，不承诺断电恢复。历史日志不会自动清理，保留期限和归档需另行制定。

## 12. 服务维护、备份与升级

### 12.1 发布目录

发布 ZIP 解压后根目录为 `certificateManage`，Java 21 环境即可运行：

```text
certificateManage/
├── lib/certificate-manage.jar  # 应用及前端
├── config/application.yml     # 应用配置
├── config/jvm.options         # JVM 参数
├── bin/                       # Windows BAT、Linux SH 维护脚本
├── logs/                      # 系统日志和启动输出
├── data/                      # 数据库及主密钥
└── run/                       # PID 和维护锁
```

脚本在源码打包时自动放入发布包。Windows 使用系统 Windows PowerShell；Linux 需要 Bash 4.4+、curl 和 flock。运行发布包不需要 Node.js 或 Maven。

### 12.2 启动、停止、重启和状态

在项目目录执行以下命令，也可以通过完整路径从其他目录调用：

| 操作 | Windows | Linux |
| --- | --- | --- |
| 启动 | `.\bin\start.bat` | `./bin/start.sh` |
| 停止 | `.\bin\stop.bat` | `./bin/stop.sh` |
| 重启 | `.\bin\restart.bat` | `./bin/restart.sh` |
| 检查状态 | `.\bin\status.bat` | `./bin/status.sh` |

Linux 解压后若没有执行权限，先运行 `chmod +x bin/*.sh`。脚本始终以项目根目录运行，避免数据库相对路径发生变化；不会注册系统服务或自动设置开机启动。

状态检查同时检查进程、首页和 `/api/v1/auth/csrf`，不登录、不执行同步。退出码 0 表示正常，3 表示已停止，1 表示异常。启动后应打开首页并登录核对。

默认端口为 8080，可通过 `PORT` 调整；直接修改配置中的访问端口或地址时，还应同步设置 `HEALTH_URL` 为本机可访问的根地址。环境变量可覆盖外置配置，修改后需重启。

### 12.3 日志位置

| 文件/入口 | 用途 |
| --- | --- |
| `logs/certificate-manage.log` | 默认系统运行日志，按 10MB 滚动，保留 30 天，总量上限 1GB |
| `logs/console.log`、`logs/console-error.log` | 启动输出；Windows 每次启动覆盖，Linux 追加 |
| 页面“执行记录”“审计日志”“发送记录” | 数据库中的业务执行与操作历史 |

启动失败时先查输出日志，再检查系统日志、Java 版本、端口及数据目录权限。审计记录不随文件日志滚动策略自动清理。

### 12.4 备份和升级

1. 停止服务，通过状态脚本确认已停止。
2. 备份原项目整个 `data` 目录，数据库 `certificate-manage.mv.db` 与 `master.key` 必须成对保留；同时备份外置配置。
3. 更新 `lib` 和 `bin`，按需合并 `config`，保留原有 `data`、主密钥及日志。
4. 使用原项目目录启动服务，检查状态、首页和 API，再登录核对资产、服务器、任务及通知规则。
5. 对升级前排队或执行中的任务检查实际结果，再决定是否重新执行。

不能用新发布包的空数据目录覆盖已有数据，不能丢失或替换原主密钥，也不要同时启动两个实例访问同一个 H2 数据库。Windows 停止使用进程终止方式；Linux 发送 TERM 并等待，超时不会自动强杀，均需确认停止后再备份。

详细环境参数见[部署维护说明](../deploy/README.md)，源码构建流程见[项目 README](../README.md#源码打包)。

## 13. 常见问题处理

| 现象 | 检查与处理 |
| --- | --- |
| 无法登录，重启后仍不是初始密码 | 初始密码只在首次初始化时创建。使用当前密码，或由其他管理员重置；检查账号是否停用 |
| 证书导入失败 | 检查完整链、格式、文件大小、解密密码及私钥匹配结果，按预览错误修正 |
| 创建证书没有可用上级 | 检查上一层证书是否存在、启用、有效并具有私钥 |
| 导入新证书后仍用旧证书 | 检查是否为自动模式、新证书整链是否已生效；自有链核对实际叶子 CN，客户链核对客户和用途；已入队实例不会换材料 |
| 自动模式提示没有可用链 | 检查候选私钥（keyStore）、启用状态、归档状态及所有链节点有效期，不只看叶子到期日 |
| 任务不能点击执行 | 检查是否就绪，配置是否完整，以及同一任务是否已有排队或执行实例 |
| 计划没有在预期时间运行 | 检查草稿/就绪、启用标识、时区和三次预览；日期与星期取交集，31 日并非每月都有；检查服务是否在线 |
| 任务每分钟执行 | 检查五列是否都为不限。选择明确的小时和分钟后保存 |
| 服务器测试成功但任务失败 | 测试不覆盖业务文件权限、原文件存在性、库密码、更新 ACL 或命令退出码；查看具体失败阶段 |
| HTTPS 连接失败 | 检查服务端证书链、主机名、有效期及额外信任配置，确认基础地址正确 |
| IS 写入或重载失败 | 检查全路径、原文件、权限、库名称、格式及密码；核对远端备份和当前文件后再重跑 |
| TN 返回成功但未看到新证书 | 核对客户 ID/idType、目标合作伙伴及已有 sign/decrypt/ssl 记录，缺失记录可能被跳过 |
| Shell 超时 | 查看已保存输出并检查远端进程，确认命令非交互且可在超时内完成，再决定重跑 |
| 没收到到期邮件 | 先保存 SMTP 并发送测试邮件，再检查启用开关、收件人、今日提醒节点和检查时间；不补发历史节点 |
