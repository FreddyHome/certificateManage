## 1. 项目目标与范围

建设仅供内部人员使用的证书管理系统，统一管理自有证书与客户公钥证书，支持 HTTPS、AS2 及通用场景，提供分层签发、证书链展示和邮件到期提醒。

MVP 包含证书管理、证书生成、客户管理、简单用户管理、SMTP配置及通知服务。所有用户均为管理员，预留角色扩展能力；客户不登录系统。

初始MVP未包含第三方同步，后续服务器管理与证书同步流程已实现，通用设计见 [服务器与同步设计](server-sync-design.md)。本轮自动选证及执行计划要求见第16节。实际角色区分及角色权限配置页面仍不在范围。管理客户 HTTPS 信任材料和 AS2 通信证书不代表自动向业务系统配置信任。

本文整合历次对话，以最新明确要求为准。用户已接受前期建议作为设计基础；未确定的参数和边界统一列入第 12 节，不将原型示例值视为确定配置。

## 2. 菜单与页面结构

| 一级菜单 | 二级菜单 | 页面职责 |

| 客户证书 | — | 终端证书列表、证书链展开、公钥证书导入及详情 |
| 客户管理 | — | 客户名称及描述维护 |

## 3. 证书通用模型与规则

### 3.1 归属、用途和层级

| 维度 | 定义 |
| --- | --- |
| 自有证书 | 保存公钥证书和对应私钥，私钥加密保存 |
| 客户证书 | 仅保存公钥证书及证书链，关联客户，用于信任客户 HTTPS 连接及 AS2 通信 |
| 用途 | 两类证书一致：AS2 / HTTPS / 通用，与归属和层级相互独立 |
| 根证书 | 根 CA，自签名，第 1 层 |
| 中间证书 | 中间 CA，由上级 CA 签发；系统生成流程中为第 2 层 |
| 叶子证书 | 终端、业务证书，非 CA；系统生成流程中为第 3 层，包含 HTTPS 服务器证书及 AS2 等证书 |

CA 类型依据证书扩展解析，根证书识别结合自签名验证。层数从根开始计算，不能按上传顺序推测。导入链超过三层的具体处理待确认，系统内创建按三层流程执行。

### 3.2 命名

- 所有证书名称取实际证书 Subject 中解析出的 Common Name（CN）。
- 导入时不提供手工名称输入，也不允许单独修改证书名称。
- 创建时填写主体 CN，生成后从实际证书解析 CN 作为名称。
- 根、中间、叶子分别使用各自 CN，不拼接客户名称。
- CN 可重名，唯一识别和去重使用内部标识及证书指纹。
- 缺失 CN 或存在多个 CN 的处理待确认。

### 3.3 信息与详情

保存和展示证书 Subject、Issuer、序列号、公钥算法、签名算法、指纹、SAN、生效时间、到期时间、用途及签发链关联；记录创建和更新信息。私钥是否存在可在详情体现，不显示私钥明文。

点击“查看”进入详情，可查看完整证书链并选择节点查看对应证书信息。链完整性不等同于目标系统已经信任该链。缺失链节点时只展示已知节点并提示，层数无法确定时显示“待确定”。新导入要求完整链，此缺失状态用于存量或异常数据，不代表允许导入残缺链。

有效期状态包括未生效、有效、即将过期、已过期；状态仅反映时间，阈值待确认。可维护用途、关联业务和备注等管理信息；名称始终来自 CN。支持按名称搜索、用途及有效期状态筛选，客户证书另支持按客户筛选。

## 4. 自有证书

### 4.1 三表布局

同一页面依次展示根证书、中间证书、叶子证书三个独立表格。三个表格列顺序完全一致：

**名称 / 用途 / 签发者 / 到期时间 / 状态 / 操作**

类型及层级通过表格分组表达，不增加类型、层数或私钥列。每个表格有独立创建入口；页面提供导入入口。根证书签发者显示自身（自签名）。保留详情与导出能力，具体导出格式待确认。

### 4.2 分层创建与签发

| 创建对象 | 上级选择 | 签发方式 | 保存结果 |
| --- | --- | --- | --- |
| 根证书 | 无 | 使用自身私钥自签名 | 第 1 层 CA、私钥 |
| 中间证书 | 必选已有根证书 | 使用所选根证书的私钥签发 | 第 2 层 CA、私钥、根关联 |
| 叶子证书 | 必选已有中间证书 | 使用所选中间证书的私钥签发 | 第 3 层终端证书、私钥、中间及根关联 |

- 各层可分别创建，按根 → 中间 → 叶子依次具备签发条件；不提供绕过上级选择的一键整链生成。
- 上级须在有效期内、具备 CA 签发能力且系统持有对应私钥。无可用上级时禁用签发并提示先创建上一层。
- 子证书有效期不得超出上级有效期，生成失败不保存不完整结果。
- 表单包含主体 CN、其他主体信息、用途、算法、密钥参数及有效期；HTTPS 叶子证书支持域名和 IP 的 SAN。
- 生成后按层归档至相应表格，保存真实签发关系和加密私钥。

### 4.3 三种导入模式

| 模式 | 文件入口 | 验证内容 |
| --- | --- | --- |
| CER / DER / CRT / PEM | 证书文件可新增、移除多行；另有一个终端私钥入口 | 完整证书链，私钥与终端证书匹配 |
| P7B / P7C | 两个文件框：证书库、终端私钥 | 解析完整链，私钥与终端证书匹配 |
| P12 / PFX | 一个文件框：包含证书链和私钥的证书库 | 提取完整链及私钥，验证匹配 |

- 分文件表单初始提供三行，分别提交根、中间和叶子证书，实际角色由内容识别。
- 根据加密情况提供私钥或证书库解密密码输入；密码输入不是额外文件框。
- 证书链须能够构建到自签名根证书，逐级验证签名及 CA 签发能力。
- 缺失链节点、私钥缺失或不匹配、解密失败、签名不匹配或不能唯一确定目标终端证书时拒绝并说明原因。
- 不支持在本流程中批量导入多个终端或多个私钥，提示拆分材料。
- 全部验证通过后才能保存；材料改变后重新验证；失败不保存部分记录。
- 导入后按层归档，已有 CA 按指纹复用并建立链关联。
- 完整链导入仅要求终端私钥，不要求上传 CA 私钥；此类 CA 仅有公钥时不能作为创建证书的签发者。

### 4.4 列表排序

自有证书三个表格分别按到期时间升序排列，较早到期的证书靠前。

## 5. 客户证书

### 5.1 列表与展开

主列表只显示终端证书，列顺序为：

**证书名称 / 客户 / 用途 / 层数 / 到期时间 / 状态 / 操作**

- 客户名称单独显示，不与 CN 合并。
- 点击证书名称在当前行下展开或收起对应中间证书、根证书，支持多行分别展开。
- 展开按终端 → 中间 → 根说明关联，显示链节点的名称、类型、层级和有效期。
- 中间及根仅作为链材料，不占据主列表独立行。
- 操作列保留“查看”，进入详情查看节点及完整证书链；支持公钥证书导出，格式待确认。

### 5.2 换证与排序

- 客户提供新证书时直接导入，与旧证书在同一列表独立并列，不建立版本关系。
- 允许同一客户、用途及 CN 对应多个不同证书，证书身份依据指纹识别。
- 默认按到期时间升序排列，较早到期（包括已过期）的记录靠前；本排序方向为本轮采用的默认设计。
- 不增加待启用、使用中或已替换状态，仍按各证书实际有效期计算状态。
- 不自动覆盖、隐藏或删除旧证书，证书各自保留详情和证书链。

### 5.3 两种导入模式

| 模式 | 文件入口 | 验证内容 |
| --- | --- | --- |
| CER / DER / CRT / PEM | 可新增、移除多行公钥证书文件 | 完整证书链及逐级签发关系 |
| P7B / P7C | 一个公钥证书库文件框 | 解析完整证书链并验证签发关系 |

不支持 P12 / PFX，不提供私钥入口及私钥密码输入，不执行私钥匹配验证。按实际内容识别，发现私钥材料即拒绝。链缺失、签名验证失败时拒绝并提示原因。名称由 CN 解析，表单保留用途和所属客户。

### 5.4 所属客户输入及保存

- 使用一个可编辑下拉输入框，既可选择已有客户，也可直接输入新名称；没有单独新增客户入口。
- 两种导入模式共用客户数据，切换模式保留客户输入。
- 点击“保存”时去除客户名称首尾空格，验证非空并检查是否存在：存在则关联，不存在则自动创建并关联，描述初始为空。
- 先完成证书链验证，再在同一事务内完成客户复用或创建及证书保存，防止失败导入产生无关联客户，并防止并发重复创建。
- 证书使用客户内部标识关联，不以自由文本替代关联。

## 6. 客户管理

- 独立菜单，存储客户名称和描述，列表显示名称、描述及操作。
- 支持新增、编辑；名称必填、描述可选，名称去除首尾空格后验证非空和重复。
- 与证书导入共用客户数据，自动创建的客户可在此补充描述。
- 修改名称后，关联证书显示新名称，内部关联不变。
- MVP 不增加客户删除；联系人和邮箱不是当前客户基础字段。

## 7. 系统管理

### 7.1 用户管理

- 所有内部用户均为管理员，具备完整管理权限。
- 提供用户名密码登录、退出、修改本人密码，以及用户列表、新增、启用、停用和重置密码。
- 停用账号不得继续访问，现有会话失效；保留至少一个可用管理员。
- 预留统一授权入口及后续用户、角色、权限关联能力，MVP 不显示角色配置页面。

### 7.2 SMTP配置

- 独立菜单，配置 SMTP 地址、端口、传输加密方式、账号、认证凭据及发件人。
- 提供保存配置、发送测试邮件和结果反馈。
- 凭据加密保存，不通过通知服务页面重复配置。

### 7.3 通知服务

- 原“过期通知”菜单更名为“通知服务”，MVP 仅通过邮件发送。
- 配置启停、收件人、提前提醒天数、每日检查时间及所用时区，复用 SMTP配置。
- 支持多个提醒节点，30、14、7、1 天为候选默认值，最终值待确认。
- 自有证书和客户证书均纳入到期管理；CA 的提醒范围及共享 CA 去重规则待确认。
- 邮件包含证书 CN 名称、归属、用途、客户（如有）、到期时间和剩余天数，不包含私钥及认证凭据。
- 同一证书、提醒节点及收件人组合发送成功后去重，失败记录原因并允许重试。
- 发送记录包括时间、收件人、证书、提醒节点、状态及失败原因。
- 收件人先以统一配置为设计基础；按客户或证书覆盖、过期后提醒、停机补发及重试参数待确认。

## 8. 数据与安全要求

- 私钥及 SMTP 认证凭据加密保存，加密密钥通过部署配置独立提供；密码采用专用密码哈希。
- 日志不记录私钥、密码及认证凭据，邮件不携带私钥。
- 管理接口要求登录；记录导入、签发、私钥导出、客户和用户维护等关键操作。
- 导入内容校验不能仅依赖扩展名，错误信息须说明问题及修正方向。
- 证书重名不视为相同证书，去重依据指纹；跨客户复用的具体规则待确认。
- 客户提供新证书时，按普通导入创建独立记录，与旧证书并列；不覆盖旧证书，不建立版本、前后继或替换关联，不增加使用状态或手动启用流程。
- 数据、私钥和配置持久化保存，重启后可继续使用；提供数据及密钥备份恢复说明。
- 完整链导入后，仅持有公钥的 CA 与持有私钥的 CA 须在详情及可用签发者筛选中正确区分。

## 9. 原型要求与边界

原型采用独立 HTML，直接通过浏览器打开，使用通用后台管理风格：深色侧栏、顶部导航、浅灰工作区、白色表格及蓝色主操作按钮。

原型覆盖菜单、三层列表、客户终端列表展开、详情、分层创建、不同导入表单、客户输入及自动创建、客户管理、用户管理、SMTP配置和通知服务。

使用演示数据，不执行真实文件解析、密码学验证、证书签发、文件导出或邮件发送。原型内客户等修改仅在当前页面会话中演示，刷新后不保留。HTML 中的名称、算法、有效期及发送结果为示例，不能作为真实校验结果或最终参数。

## 10. 核心业务流程

1. 创建自有证书：创建自签名根 → 选择根创建中间 → 选择中间创建叶子 → 按层归档并展示链。
2. 导入自有证书：选择格式 → 提交链及终端私钥或完整容器 → 验证链和私钥 → 保存并分层展示。
3. 导入客户证书：选择格式 → 提交公钥链、用途及客户 → 验证链 → 保存时复用或自动创建客户 → 主列表显示终端，展开显示上级。
4. 到期通知：配置 SMTP并测试 → 配置通知规则 → 定时检查 → 发送邮件 → 记录成功或失败，成功去重、失败可重试。

## 11. MVP 验收标准

| 编号 | 场景与预期 |
| --- | --- |
| AC-01 | 菜单严格符合第 2 节，无独立证书生成菜单；SMTP配置与通知服务分离 |
| AC-02 | 自有证书同页三表，客户主列表仅终端；字段及顺序符合第 4、5 节 |
| AC-03 | 名称解析自 CN，无手工名称输入；客户作为单独列 |
| AC-04 | 根可自签名创建；中间必须选根，叶子必须选中间；不可使用无私钥或失效 CA 签发 |
| AC-05 | 自有三种导入模式的文件框数量、增减行及密码输入符合规则 |
| AC-06 | 不完整链、错误签名、缺失或不匹配私钥、错误解密密码均拒绝保存，不产生部分记录 |
| AC-07 | 客户只支持两种导入模式，无私钥和 P12/PFX 入口；检测到私钥内容拒绝 |
| AC-08 | 客户输入可下拉也可直接输入；保存时已有客户复用，新客户自动创建；无独立新增入口 |
| AC-09 | 客户证书可展开中间及根；详情能选择链节点；异常缺失链明确提示 |
| AC-10 | 客户管理可新增、编辑名称和描述；与证书导入共用数据，改名不破坏关联 |
| AC-11 | 用户均为管理员，支持登录及账号维护；停用后不可访问，预留角色能力 |
| AC-12 | SMTP可配置和测试；通知服务可配置规则、查看记录，邮件发送成功去重，失败可追溯 |
| AC-14 | 同一客户新旧证书独立并列，无版本和替换状态；列表按到期时间升序排列 |
| AC-13 | 敏感数据加密保存且不进入日志；重启后业务数据及配置保留 |

验收中的未定参数须在实施前按第 12 节补齐；原型演示不等于真实系统通过上述验收。

## 12. 待确认事项

1. 部署环境、访问方式及数据规模；技术栈与数据库已确定，见第 14 节。
2. 用途是否允许多选；客户证书是否允许关联多个客户；客户名称大小写等唯一性规则。
3. 缺失或多个 CN 时的命名策略。
4. 导出格式、私钥导出保护方式及 CA 私钥可导出范围。
5. 生成算法、密钥长度、默认有效期、用途扩展和 AS2 参数。
6. 导入超过三层链的归档和展示方式；仅有公钥 CA 后续补充私钥的方式。
7. 已过期证书的导入策略，以及链验证中有效期等检查的拒绝或提示边界。
8. 跨客户及跨归属证书去重、共享 CA 关联和提醒规则。
9. 即将过期阈值、提醒节点、CA 提醒范围、收件人覆盖、时区、重试及停机补发参数。
10. 证书删除、归档及数据保留规则；客户换证采用独立并列记录，不建立版本。
11. 密码策略和会话有效期；首次初始化账号已确定，见第 14 节。

角色权限配置及更多通知渠道另行设计。第三方同步现已明确采用服务器配置引用、可编辑组件流程、定时与立即执行；通用设计见 `server-sync-design.md`。具体目标系统的HTTP导入契约在任务配置和联调时确定。

- 不做前后端独立部署：Vue 3 生产构建产物由 Spring Boot 提供，统一打包为可执行 JAR，同源访问。
- H2 使用外置数据目录中的文件持久化，避免重启丢失；MVP 为单实例部署。
- 首次初始化账号为 `admin`，初始密码为 `123456`；密码哈希存储，重启不得覆盖修改后的密码或已有账号。

## 15. 工程结构要求（2026-11-08 确认）

- 前后端源码目录采用各自框架的标准组织方式，单仓库维护，统一构建部署。
- 后端使用 Maven 标准 src/main/java、src/main/resources 和 src/test 目录，并按业务模块组织。
- 前端使用 frontend 目录，按页面、组件、路由、接口、共享状态和类型分开管理。
- 生成资源、依赖、运行数据、日志及秘密不进入源码仓库；详细目标目录见设计文档第 16 节。
# 自有证书删除补充

- 自有证书三个表格均提供删除操作，删除前二次确认。
- 后端在事务中检查引用：其他未删除资产的证书链包含当前证书、以当前证书为签发者或关联当前签发资产时，禁止删除并显示引用证书名称和ID。检查范围包含客户证书链。
- 采用逻辑删除，列表、详情、导出及签发选择不再提供已删除资产，保留证书材料、加密私钥、审计和通知历史；重新导入同一证书可恢复资产。
- 已删除证书不再扫描或投递通知，已有通知正在发送时暂不允许删除。客户证书本轮不提供删除入口。

# 证书创建主体信息补充

根、中间、叶子证书创建表单均提供国家/地区（C）、省/州（ST）、城市（L）、组织（O）、部门（OU）字段，除CN外均可选。国家使用有效的ISO两位代码，例如CN，保存时统一大写；其余字段最多128字，禁止控制字符。字段写入实际X.509证书Subject，证书名称仍取CN。上级Issuer使用所选签发证书的完整Subject，不继承或覆盖当前证书填写的地址。

# 统一日志（2026-11-10明确）

所有业务操作日志和后台执行日志统一写入日志表，核心字段为执行人、执行时间、操作/执行内容。手动任务使用发起用户，定时任务标识为系统。成功和失败均记录，提供系统管理下的“审计日志”查询；只读，不提供日志修改删除。凭据和报文原文不写日志。

# HTTP标准请求组件（2026-11-11）

HTTP步骤为通用请求组件，支持GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS，配置Path、Query参数、Headers和请求体类型。请求体支持NONE、JSON、FORM（urlencoded）、MULTIPART、BINARY、TEXT。Query、Headers、表单字段通过可增删键值行编辑；JSON和文本通过正文编辑。GET/HEAD固定无请求体，JSON/表单/文本及无请求体调用不要求选择证书或产物；文件请求继续支持前序Store及直接导出证书。认证沿用所引用服务器的配置，现有HTTPS校验、超时、响应成功判定及脱敏日志规则保持。

# SFTP移动/重命名组件

SFTP步骤增加操作类型：UPLOAD（原上传）或MOVE（移动/重命名）。MOVE引用服务器别名，配置源文件绝对路径、目标文件绝对路径及覆盖开关，无需选择证书或前序产物。仅支持远程常规文件，目标目录需存在，不允许相同源/目标或`..`路径段；默认目标存在则失败且不删除源文件。使用SFTP rename协议，不执行远程Shell、不降级为复制后删除。操作记录执行人、时间、源/目标路径及结果，失败保留安全诊断原因。

## 16. 证书自动选取与执行计划（2026-11-16确认）

### 16.1 自有证书自动换新

- IS keyStore 更新组件支持“自动选择同 CN 到期最晚的可用链”和“指定证书”。自动模式以用户所选自有叶子证书的实际 CN 为匹配基准，精确匹配同 CN 的自有叶子证书，不附加用途条件。
- 候选须含私钥、已启用、未归档、未删除，且整条证书链当前均在有效期内。按叶子证书到期时间降序选择；相同到期时间按资产 ID 降序稳定选择。
- 每次计划触发或列表执行入队时重新查询。新证书导入并生效后，下一次入队即可采用，不必等旧证书过期。系统不自行签发、续期或下载证书。
- 基准只确定匹配 CN，其过期、停用、归档或软删除不阻止选择其他同 CN 有效链。软删除保留的材料仍可用于读取基准 CN；没有可用候选时本次入队失败，不擅自改用其他 CN。
- 入队后冻结所选证书、完整链和私钥引用；后续导入的新证书仅影响下次执行。指定证书模式始终引用指定资产，失效时失败，不自动替换。
- 本规则适用于 IS keyStore 业务组件；旧通用“制作 Keystore”固定条目继续兼容，不因本次需求自动改为按 CN 选证。

### 16.2 客户证书自动选取

IS truststore / TN 证书更新业务组件的自动模式，按同一客户、同一用途选择已启用、未归档/删除且整链有效、终端到期最晚的证书链，每次入队重新查询并冻结。到期相同按资产 ID 降序。指定链不自动换新；truststore 手动调整链节点勾选会固定为指定链。原固定 TNPartner HTTP 组件按客户及用途自动选证的兼容行为保留。

### 16.3 五列执行计划

证书同步通过以下五列滚动多选设置执行时间，不提供“仅手动执行 / 定时执行”的方式选择。需要立即执行时，使用任务列表中的“执行”按钮，遵守原有就绪校验和互斥规则。

| 选择列 | 可选范围 | 未选具体值或全选 |
| --- | --- | --- |
| 月份 | 1–12月 | 不限月份 |
| 日期 | 1–31日 | 不限月内日期 |
| 星期 | 周一至周日 | 不限星期 |
| 小时 | 00–23 | 不限小时 |
| 分钟 | 00–59 | 不限分钟 |

同列多选表示满足其中任意值；不同列必须同时满足。日期与星期同时选择时取交集。没有所选日期的月份会跳过，不自动移到月末；整个组合没有未来执行时间时禁止保存并提示。按星期执行不自动排除法定节假日或处理调休。新五列计划在匹配分钟的第0秒触发。

新任务默认每天02:00、北京时间：月份/日期/星期不限，小时选02，分钟选00。全列均不限表示每分钟触发，不表示停用计划。

### 16.4 保存、预览及旧任务

- 草稿保存计划但不运行；五列计划在任务设为“就绪”并保存后自动启用。现有未启用任务不会因页面打开、预览或升级而被批量启用，用户以就绪状态在新界面保存后按计划运行。
- 每次选择变化后实时展示中文规则和最近三次具体计划时间；草稿也可预览，注明尚未启用。预览按所选时区显示日期、星期和时间，不依赖流程步骤、证书或服务器是否填写完整，不保存任务、不触发同步。
- 旧常用计划无损转换为五列选择；月底、秒级及其他无法转换的特殊规则保留原表达式，放在折叠的高级设置中。旧秒级规则的预览和列表时间保留秒数，不静默改成默认计划。
- 任务列表显示中文执行计划和下次计划时间，保留“执行”“记录”等操作。历史未启用计划明确标识“未启用”。
- 计划时间表示触发入队时间，不保证立即开始或成功；同一任务不并行运行。前次未结束时保留本次未入队原因，失败不自动重试。停机遗漏不逐次补跑，恢复扫描时可能处理一次已到期触发，再推进未来计划。

### 16.5 本轮验收项

| 编号 | 验收要求 |
| --- | --- |
| AC-SYNC-01 | 多个自有叶子同 CN 时，IS keyStore 自动模式采用含私钥、整链有效且到期最晚者；其他 CN、已禁用/归档/删除候选不被选中 |
| AC-SYNC-02 | 新证书导入后下一次入队重新选取；已经入队的实例保留冻结链和私钥；基准失效不阻止选择其他有效链 |
| AC-SYNC-03 | 五列均可多选，支持31日；空/全选表示不限；跨列交集、无该日期跳过及无未来时间拒绝均可验证 |
| AC-SYNC-04 | 页面不区分手动/定时；草稿仅保存，就绪保存启用；手动通过列表执行；旧任务不批量启用 |
| AC-SYNC-05 | 修改选择后只显示当前规则的三次预览；旧响应和错误不残留为成功结果；预览不保存或执行业务任务 |
| AC-SYNC-06 | 旧规则无损转换或保留原文，特殊秒级预览精度准确；重启保留数据、主密钥及计划参数 |

## 17. 标准部署包与维护脚本（2026-11-16确认）

发布包根目录固定为项目文件夹`certificateManage`：`lib`存放可执行JAR，`config`存放应用配置及JVM参数，`bin`存放维护脚本，系统日志默认写入`logs`。数据与主密钥放在根目录`data`，进程记录放在`run`，不得把已有数据库、主密钥和运行日志打进发布ZIP。

维护脚本分为Windows `.bat`和Linux `.sh`两套，均提供启动、停止、重启和状态检查。从任意工作目录执行时均以项目根目录运行；启动不得重复创建同一实例，停止须核对PID对应的应用身份，状态须同时反映进程与首页/API探测结果。外置配置可覆盖JAR默认值，升级保留已有data及原主密钥。仍以单个包含前端与依赖的Spring Boot JAR运行，不要求额外部署Node服务。

## 18. P1 性能优化（2026-11-16）

- 证书管理与归档页面采用服务端筛选和分页，每页20条；自有根、中间、叶子三表分别翻页，保持原有到期时间升序、相同到期按ID升序。客户归属、用途、状态、CN/客户包含搜索及启停、归档、恢复等操作保留。
- 搜索输入300ms防抖，筛选变更回到第一页；迟到响应不得覆盖当前条件，操作造成末页为空时自动回退到有效页。
- 普通、归档、详情查询的证书状态映射不得逐行查询相同提醒策略，也不得在结果映射期间额外占用连接。
- 前端缩减未使用组件与样式，保留中文、消息、确认框和加载提示。内容哈希静态资源可长期缓存，HTML重新验证，敏感API继续禁止缓存；文本响应支持gzip。
- 同步页面独立数据并行加载，保存时复用服务端返回的任务详情，减少无意义重复查询；自动选证、计划、执行互斥及已有任务不变。
- 原全量证书接口保留兼容，新增分页接口供管理列表使用。本轮不提高任务并发、不迁移数据库、不删除审计历史；后续P2见[性能报告](performance-review-2026-11-16.md)。

## 19. P2 性能优化（2026-11-16）

本节是在P1之后的增量，当前并发和审计恢复规则以本节为准。

- 服务器列表批量读取公开配置及凭据是否已配置的标记，普通读取不逐台解密秘密；旧配置允许一次兼容补全，空密码仍表示保留。
- 单次校验或执行复用公钥证书链，保存与入队复用相同服务器快照。自动选证仍要求整链有效；冻结快照、同CN规则及执行时停用/归档校验保留。
- 执行线程与扫描、心跳分离，默认最多2个独立任务并行。同一任务不重入，共享任意目标服务器的实例排队等待；失败不自动重放远端操作。
- HTTP客户端按不可变配置和信任材料复用，缓存有界；配置更换后使用新客户端，每次调用仍检查服务器和信任证书可用性。
- 原始审计支持压缩后加密并完整还原。摘要写库失败及原文异步写库采用有界加密本地待写箱，数据库恢复或进程重启后幂等补写；不自动删除历史。容量耗尽时明确报告失败并在远程操作前背压。
- 审计页面采用游标前后翻页，筛选或刷新回到首页，详情支持刷新及全局待写提示；旧页码API继续兼容。历史未采集的原文仍无法补回。
- 会话与证书链合并重复在途请求并有界缓存，退出、401、改密和相关证书修改后作废；服务端鉴权不变。
- 提醒扫描按时区和当天阈值筛选未投递的证书与收件人，保留去重、重试和当天新增资产语义。扫描与投递分离，每批邮件复用连接和配置快照。
- 提供仅管理员可读的性能API，观察API耗时/错误、连接池等待/超时、后台积压、审计待写、HTTP发送/响应累计耗时和JVM/GC，不返回业务正文、凭据或URL参数。无外部监控依赖。

配置与边界见[设计第20节](design.md#20-p2-性能实现2026-11-16)、[P2验收](performance-p2-verification-2026-11-16.md)。本轮不实现审计保留期限或自动归档清理，不承诺断电恢复或未实测的外部服务器吞吐。
