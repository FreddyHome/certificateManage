# P2 性能优化实施计划

> 用户已要求继续P2，依据[性能报告](performance-review-2026-11-16.md) OPT-06～OPT-16执行；采用测试驱动、独立任务并行及最终整体审查。保留工作区原有P1与审计改动，不重置或覆盖。

**目标：** 控制后台并发、重复查询、内存与历史增长的成本，并提供可观测的性能指标。

**架构：** 保持Java21/Spring Boot/JdbcTemplate/H2/Vue3。配置、证书公钥解析按版本或单次操作复用；执行使用有界线程池和每服务器限流；审计使用加密压缩载荷与可靠本地待写队列，数据库恢复后补写，不重放远端操作。保留兼容API并增加可选游标与管理员指标接口。

## 全局约束

- 沿用原data和master.key，不触发真实远程同步、命令或通知；修改通过完整生产验证后重新打包、备份并重启原目录服务，检查首页/API。
- 不更改自动选证、整链有效性、冻结快照、即刻停用校验、同任务互斥、通知节点和重试语义。
- 不删除审计或自动清理历史；归档保留期限属于业务决策，本轮只优化检索与建立可观测依据。
- Java沿用Freddy作者与中文注释规范；新类日期2026-11-16；无新外部服务，不更换数据库引擎；Flyway只增加兼容的索引和可空幂等列。
- 持续记录行为回归RED/GREEN和有效测量；所有大文件/故障实验使用隔离数据与本机桩。

## 任务和边界

### A. 数据查询与工作流（OPT-06/07/08/13/14）

- [x] 服务器列表/详情使用批量公开配置与非秘密配置标记，旧版本允许一次兼容补全，普通列表不逐台读取并解密秘密。
- [x] 连接读取移出RowMapper，避免第二连接；同次校验或执行复用不可变公钥链，数据库有效期筛选候选；每步骤继续实时检查启用/归档。
- [x] 同次保存/入队去重服务器快照、批量引用和轻量历史投影，保持锁内修订与引用一致性，不将远端操作放入事务。
- [x] 同步执行与扫描/心跳分离，有界执行线程池，默认最多2个不同任务并行，每目标服务器默认1个远程操作；同任务不重入，关闭等待有界。
- [x] 覆盖列表SQL上界、凭据留空保留、配置版本、执行并行/互斥/关闭和选证回归。

### B. 远程客户端与原始审计（OPT-10/11/12）

- [x] 有界复用HTTP客户端与TLS上下文，以不可变配置版本和信任材料为键，配置变更后新请求采用新版本；保留停用检查和HTTPS身份校验。
- [x] HTTP原始载荷以字节形式交给流式JSON编码，避免先构造第二层Base64字符串；压缩后加密存储，兼容解密旧JSON载荷并完整还原。
- [x] 原始审计待写数据先可靠保存为本地加密文件，不在无界堆队列中积压；批量补写、幂等去重、限制每批字节，重启恢复。读取详情不再同步清空200条队列。
- [x] 定义磁盘积压上限与背压/失败信息，不静默丢记录、不因审计失败重放远端副作用；隔离数据源的待写目录以避免测试与正式库串写。
- [x] 覆盖数据库故障/恢复、重启恢复、旧载荷、大字节载荷、客户端复用/版本更换/关闭，保留所有现有远程桩测试。

### C. 前端与通知（OPT-09/15）

- [x] 会话请求共享在途结果，布局复用，退出/改密/401作废；不取消服务端逐请求鉴权。
- [x] 编辑会话内相同资产链请求合并/有界缓存，导入、启停、归档、刷新或卸载后失效，旧响应不得覆盖新选择。
- [x] 通知按时区和今日阈值区间下推SQL，查询未投递的资产×收件人，保留唯一约束兜底；支持当天新资产和策略变更。
- [x] 每批投递复用邮件连接/配置快照，在途邮件使用同一配置，保留Message-ID、失败重试、停用过滤和有限批量；发送与扫描分离避免慢SMTP阻塞扫描。
- [x] 覆盖首次/重复会话、401、链失效、时区/DST日期、重复扫描、新增资产、部分发送失败和重试。

### D. 检索与观测（OPT-10/14/16，主线程）

- [x] 保留审计页现有筛选/状态聚合变更；摘要补写使用可靠有界待写机制，避免第二个无界内存队列。
- [x] 审计列表增加可选游标（时间+ID）和可选总数，保留旧分页；使用明确字段投影、匹配过滤排序索引；不删除历史。
- [x] 管理员性能API提供进程/API耗时和错误、Hikari等待与超时、工作流排队时长/积压、通知积压、审计待写字节、HTTP发送/响应累计耗时及JVM/GC（SSH/SFTP分阶段指标未实现）；不暴露凭据、URL参数、私钥或正文。
- [x] 文档标明配置默认值、兼容边界、测量方法和未测场景。
