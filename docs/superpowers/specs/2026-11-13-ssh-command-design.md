# SSH Shell 命令执行步骤

状态：已实施并验证。下文默认超时、输出上限和退出码规则已落实为实现行为，属于实现时采用的设计选择；用户明确要求仍以“独立步骤、固定参数、服务器菜单配置并在组件选择”为准。当前范围及验收边界见 [需求与设计核对基线](../../../doc/requirements-design-review-2026-11-14.md)。

## 需求

新增独立的 SSH 步骤，所有输入均为步骤中保存的固定参数，不消费前序步骤文件或证书，不产生供后续步骤消费的文件。现有 SFTP 上传、移动和读取逻辑不改。

## 接入方案

现有 RemoteTransport 已通过 Apache MINA SSHD 建立 SSH 连接，服务器管理已支持密码和私钥认证。用户确认在服务器管理中新增 SSH 类型，Shell 组件选择已保存的 SSH 服务器；增加独立 SSH 执行通道与步骤类型，执行命令不要求远端提供 SFTP 子系统。

已讨论复用 SFTP 服务器类型和单独维护 SSH 类型两种方式；采用用户选择的独立 SSH 服务器类型，共享字段校验和加密凭据机制。SFTP 操作保持文件传输职责。

## 拟定行为

- 步骤类型：SSH；界面名称：Shell 命令执行。新增任务和已有任务均可添加，任务可仅包含 SSH 步骤。
- 固定参数：服务器、命令内容、执行超时。支持多行命令；不做前序步骤变量替换，不开放交互式终端。
- 使用所选服务器的用户名、密码或私钥认证，以对应远端用户身份执行。命令通过远端 SSH exec 通道交由远端配置的 Shell 解释。
- 命令内容在任务入队时随配置冻结。连接配置继续沿用现有快照及停用检查。
- 建议默认执行超时 60 秒，可配置 1–300 秒；连接和认证超时沿用服务器配置。
- 以远端最终退出码 0 判定成功；非 0、缺失退出码、超时或连接异常均判为失败，并停止后续步骤。多行脚本遵循远端 Shell 的退出码规则，不自动插入 set -e。
- 同时采集标准输出和错误输出，避免单流阻塞；每流最多保留 1 MiB，超出后继续排空并标记截断。
- 执行详情记录命令、输出、退出码、耗时及异常；原始内容沿用现有加密审计，列表显示摘要。
- 超时关闭通道并标记失败；不承诺远端衍生或后台进程被终止，不自动重试。

以上默认值、输出上限及退出码规则为实现建议，用户已明确的要求为独立步骤、固定参数和保留现有 SFTP 功能。

## 验证及交付

验证无文件输入的保存、校验与执行、配置快照、停用服务器、正常输出、错误输出、非零退出码、超时及输出截断，并回归现有 SFTP 功能。通过对应前后端检查后重新打包，在原项目工作目录沿用现有 data 数据库和主密钥重启服务，检查首页与 API。
